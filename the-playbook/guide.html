Installing & using a Claude Skill

A Skill is a folder with instructions in it — no code required. This page walks through what it actually does, how to make one live, and how to use it day to day.

1What a Skill actually is

Every skill in this library is a folder containing a SKILL.md file — plain Markdown, no code required. It has two parts: a short name and description that Claude keeps loaded at all times for every skill you have installed (this costs almost nothing, roughly 100 tokens per skill), and the full instructions body, which Claude only reads once your request actually matches that description.

This is called progressive disclosure, and it's the whole reason you can have dozens of skills installed without them cluttering every conversation:

2Install a skill (make it live)

The skills in this library live in a separate project (claude-skills-library/) as the source of truth. To actually use one, it needs to be copied into a folder Claude Code looks in — either ~/.claude/skills/ (personal, works in every project) or a project's own .claude/skills/ (only active in that project).

To install everything at once:

cp -r claude-skills-library/skills/* ~/.claude/skills/

Or just one skill:

cp -r claude-skills-library/skills/swot-strategic-review ~/.claude/skills/

3Just describe your task

Once installed, you don't invoke anything by name. Describe what you need in normal language, and Claude checks it against every installed skill's description automatically:

"Help me figure out why our September bookings dropped"

… will likely trigger root-cause-five-whys or mece-problem-structuring on its own, because their descriptions say exactly when to use them.

4Be explicit when it matters

If a task is ambiguous, or you want a specific framework rather than whichever one Claude guesses is closest, just name it:

"Use the swot-strategic-review skill on our current position"

You can also chain skills in one request — "run a SWOT, then turn it into an executive summary" pulls in two skills in sequence.

5Using it on claude.ai instead

Skills work a bit differently on the website/app versus this terminal tool. Zip a skill folder, then upload it under Settings → Features → Skills (requires code execution enabled, Pro/Max/Team/Enterprise plans). Skills uploaded there are separate from Claude Code skills — install in both places if you want it available everywhere.

zip -r swot.zip swot-strategic-review

6Writing your own

Every skill in this library follows the same shape — copy it as a starting template:

---
name: your-skill-name
description: What this does, in one sentence. Use when [specific situation].
---

# Your Skill Name

## When to use this
## When NOT to use this
## Workflow
## Output format
## Common pitfalls
## Quality checklist

The description field is the one that matters most — it's literally what Claude matches your request against, so it has to say both what the skill does and when to use it. Keep the name lowercase-hyphenated, under 64 characters, and never containing "claude" or "anthropic."

Full detail on every rule (naming limits, security notes, where skills sync and where they don't) lives in GUIDE.md in the source project.
